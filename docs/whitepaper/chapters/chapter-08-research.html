Chapter 8: AI research agents

ModelAutoResearcher is a proposed agent for planning and running modeling experiments in a Ploinky workspace. Its intended output is a model or comparison with the data preparation, evaluation and instructions needed to review it.

Begin with an objective

A user might ask it to classify documents, adapt a language model to a domain, compare embedding models or test information-extraction methods. The agent would choose a working profile based on the task, available data and hardware, confidentiality rules, time and budget.

The experiment cycle

  1. Define the objective. Convert the request into a research plan and acceptance criteria.
  2. Inspect the data. Check formats, missing values, duplicates, label quality, imbalance, leakage and sensitivity. Text, tables and graphs require different checks.
  3. Plan the experiment. Choose the base model, method and validation strategy. Candidates include LoRA, QLoRA, supervised fine-tuning, classical models, gradient boosting and embedding evaluation.
  4. Prepare the dataset. Clean, transform, deduplicate and split the data, recording each step. If Synthetic Data Lab produces extra examples, preserve their source, schema, version and filtering rules.
  5. Run the experiment. Execute training, adaptation or comparison inside the allowed environment. Record resource use, metrics, errors and early stopping.
  6. Evaluate. Compare against baselines and alternatives using quantitative metrics, representative examples and failure cases.
  7. Deliver. Save the model or adapter, configuration, processed data, evaluation report, model card, limitations and inference instructions.

What the project keeps

The useful memory is broader than model weights. Training recipes, dataset observations, failed configurations, benchmark results and filtering rules can help with later experiments.

The agent would store these findings as Knowledge Units in the relevant workspace or project folder. Records can be marked experimental, checked automatically or approved by a person. Later tasks can retrieve them without treating every past conclusion as established fact.

What needs to be demonstrated

The full cycle remains a development goal. Each supported task needs evidence that its data checks, experiment selection and evaluation work under the stated resource limits. A useful failed experiment should still return logs, partial artifacts and a clear account of where it stopped.
