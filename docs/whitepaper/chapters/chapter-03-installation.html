Chapter 3: Installation and architecture

AssistOS uses Explorer for the workspace and Ploinky for packaged capabilities. Other components add agent execution, reasoning checks, collaboration and data controls. This is an architecture overview; individual projects document their supported installation paths.

Start Explorer

Install Ploinky and configure a repository containing the Explorer package. The documented startup command is:

ploinky start explorer

The package configuration determines the workspace setup, dependencies and default agents. Check its installation instructions for the version you are using.

Ploinky supports Docker or Podman containers. Lighter sandbox options include bubblewrap on Linux and seatbelt through sandbox-exec on macOS. Select the runtime required by the package and inspect its requested access.

Workspace and execution

Achilles IDE, the AssistOS Explorer, combines file navigation, editing and agent controls. Its integrations include OnlyOffice, repository operations, the Copilot and WebMeet.

Ploinky starts capabilities in configured containers or sandboxes and manages workspace access. Isolation reduces exposure to the host; it does not make arbitrary code safe under every configuration.

Agents and tasks

AchillesAgentLib provides patterns for agent execution and skill coordination. Achilles CLI and the Copilot connect instructions to skills, Knowledge Units and other available agents.

Domain agents specialize in research, analysis, security or verification. The Backup Agent is intended to preserve workspace files, specifications and knowledge records. Robot identities and homes give these replaceable capabilities a persistent user-facing role.

Reasoning and validation

AGISystem2 explores explicit knowledge representation and logical checks. MRP-VM, the Meta-Rational Pragmatic Virtual Machine, organizes task execution around interpreters, policies, traces, validation and saved state.

These components can check represented constraints. Their presence does not establish the truth of every generated claim.

Communication

WebMeet provides conferencing and shared work with agent participation, blackboard controls and AudioAgent voice integration. Ploinky Wormhole explores direct communication between workspaces using local identities and policy.

Data and evidence

LightDSU describes encrypted data units with signed event histories. Its provenance profiles include W3C PROV, FHIR, GxP and RO-Crate. The DPU Agent controls access to local sensitive data and approved computations.

The Trustworthy AI Agent and Security Guardian Agent are development directions for evaluation, monitoring and evidence collection. Their reports can reference external frameworks; certification requires separate validation.

Reusable knowledge

Agentic knowledge units, or AKU, keep findings in local files with aggregated indexes and BM25F search. A context pack selects relevant records for the next task.

How the parts meet

A person assigns a task in the workspace. A Robot uses a packaged capability on the allowed project files. Tools run checks, and the task records outputs and failures. The person reviews the result in Explorer or with colleagues in WebMeet.

That path should work for one person on one machine before it needs a larger deployment. Research components can join it when they solve a demonstrated problem.
