Chapter 9: Trustworthy AI Agent

The Trustworthy AI Agent is a development direction for checking datasets, models and deployed behavior. Its intended outputs are findings with evidence, risk reports and specific steps for correction.

What needs checking

A model can score well on a benchmark and still fail on a particular population or workflow. Tests need to cover the intended use, including data leakage, bias, unsupported outputs, prompt injection and changes after deployment.

The agent is intended to organize these checks across the system's lifecycle. It cannot replace domain review or establish compliance by itself.

Before training

Inspect data quality, class balance, test-data contamination and suitability for the task. Flag personal information, sensitive fields and missing licensing information. Record the affected data and the method used to detect each issue.

Before deployment

Compare model candidates across relevant subgroups and perturbations. Test robustness, explainability and the safety requirements of the use case. For language models, include unsupported claims, prompt injection, output-format errors and harmful outputs.

During operation

Monitor data drift, performance changes, incidents, unusual costs and policy violations. An alert should state what changed and what evidence supports it. Monitoring can miss failures, so teams still need a response and recovery process.

Reports

A finding should identify the check, observation, severity, supporting evidence and proposed remedy. A short decision report can link to technical tests, execution records and retest criteria.

Reports may map findings to ALTAI, NIST AI RMF, the EU AI Act or ISO/IEC 42001. Such mappings help organize evidence. Whether the system meets a particular obligation requires separate assessment.

Reuse what the tests establish

Validated tests, recurring failure patterns and successful remedies can become Knowledge Units. Record their scope and limitations so later checks can reuse evidence without assuming it applies to every model.

The first useful milestone is a narrow evaluation that another person can rerun and inspect. Broader continuous monitoring should build on those results.
