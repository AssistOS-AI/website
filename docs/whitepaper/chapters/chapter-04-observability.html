Chapter 4: Observability

A person supervising a Robot needs to know what is running, what changed and what requires a decision. Useful status includes reading sources, running tests, waiting for input, completed and failed. A generic "thinking" indicator is not enough.

Model providers

AchillesAgentLib supports OpenAI-compatible interfaces and direct integrations with Google Gemini and Anthropic APIs. Provider support depends on the adapter and model features in use.

Different tasks may use different providers. A project should record which model and capability produced an important result so the team can investigate it later.

Soul Gateway

Soul Gateway is the proposed common point for model configuration, routing and request monitoring. Its intended responsibilities include:

  • Configuring provider connections, credentials and model selections.
  • Routing requests according to task, cost and performance policy.
  • Recording request metadata, token use and execution times.
  • Reporting costs and provider availability.

Prompt and response logging needs a retention and access policy because it may contain project data. Operational records should describe actions and outcomes without depending on hidden model reasoning.

Evidence for review

Task history should connect the inputs, model and capability versions, tool actions, checks, approvals and output files. A user should be able to distinguish a successful result from a stalled or failed task.

For code, that may mean a diff and test output. For research, it may mean sources and a draft. The evidence should fit the work being reviewed.

The Soul Gateway architecture and integration details remain in development. This chapter describes its intended responsibilities.
