Chapter 13: NeuroVSA

NeuroVSA explores how an agent can choose and test representations for a structured problem. Its research covers Vector Symbolic Architectures, or VSA, Hyperdimensional Computing, or HDC, and Holographic Reduced Representations, or HRR.

Choose through experiments

VSA methods represent information with high-dimensional vectors. Operations such as binding, bundling, permutation, cleanup and similarity search encode and retrieve structure. Different representations preserve different properties and have different costs.

NeuroVSA treats the choice as an empirical question. A useful comparison needs a problem class, an encoder, a baseline and an acceptance test. The project should retain unsuccessful experiments as well as successful ones.

The proposed components

  • A Problem Interpreter converts the request into constraints, data types, outputs and validation requirements.
  • A Representation Registry records each backend's operations, cost, encoders and known failures.
  • An Experiment Engine compares dimensions, encoders, noise models, cleanup methods and task decompositions.
  • A Validation Layer runs statistical and symbolic checks, baselines, ablations and reproduction tests.
  • A Knowledge Unit Store saves results, parameters and failure records.
  • A Meta-Learning Planner uses those records to choose what to try next, including when to reject VSA for a task.

The language model helps interpret requests and propose experiments. Representation backends, symbolic tools and statistical evaluators perform the checks.

Representations under study

  • Binary Spatter Codes for symbolic binding, role-value records and provenance frames.
  • MAP and bipolar HDC for bundling, classification and feature aggregation.
  • HRR for approximate compositional structure and continuous binding.
  • Sparse binary representations for membership tests, routing and approximate filtering.
  • Graph-VSA hybrids for explicit relations combined with similarity retrieval.
  • Genomic hypervectors and k-mer HDC for sequence sketches and cohort comparisons.
  • Hierarchical and ultrametric encodings for taxonomies and ontologies.
  • Exact symbolic tools for rule execution and constraints that need exact checks.

Some backends intentionally support only part of the usual operation set. Their contracts should state which properties they preserve and which they omit.

The research loop

A new task, dataset or benchmark failure leads to a hypothesis. The agent runs controlled experiments, compares baselines and tests sensitivity to parameters. It saves the evidence as Knowledge Units.

Supported selection rules can enter the active registry. Rules that fail repeatedly should be retired. This is a search over representations and validation methods, with a record of why each choice was made.

Possible applications

Literature analysis could retrieve candidate claims and contradictory evidence. Legal analysis could compare obligations and exceptions before an exact review. Genomics could use sequence sketches for similarity search. Workflow analysis could compare experiments through explicit graphs. Security experiments could classify local event streams.

These are research targets. Each needs task-specific benchmarks and comparisons with simpler methods.

Limits

  • Missing information does not establish that a claim is false. The system must distinguish unknown facts from closed-world conclusions.
  • Encoding facts does not identify every relevant consequence. Dependency rules still matter.
  • Vectors need external grounding in measurements, protocols or reviewed definitions.
  • Noise and limited capacity make approximate retrieval unsuitable as the sole basis for exhaustive or formally certain conclusions.
  • An encoder can discard structure that later operations cannot recover.
  • Performance on one problem class does not establish performance on another.
  • Associations can suggest causal hypotheses; they do not prove causality.

The deliverable is an experimental record of which method worked for which task, under which conditions. Claims of improvement need that evidence.
