Chapter 5: The Ploinky environment

Ploinky packages and runs tools, agents and services for AssistOS. It keeps their dependencies and execution settings together so a capability can be installed and started without rebuilding its environment by hand.

What a Ploinky Agent contains

In Ploinky, an agent is a runnable package. It may contain a script, command-line tool, MCP server, model endpoint, AI agent or web application. Repositories group related packages and can be enabled or disabled.

A Robot is the persistent worker a user delegates to. A Ploinky Agent supplies a capability that worker can use. The package does not have to contain an autonomous AI system.

Runtime and configuration

  • Docker and Podman provide container environments with configured resource access. Bubblewrap on Linux and seatbelt on macOS provide lighter process sandboxing options.
  • A manifest.json declares the package's image, dependencies and commands.
  • WebConsole, WebChat and dashboard interfaces expose supported command-line and service interactions in the browser.
  • Repositories provide a way to distribute and version related capabilities.

Inspect mounted folders, credentials and network access when configuring a runtime. Isolation depends on those choices; containers do not provide complete separation from the host under every configuration.

Development and use

Ploinky supports local development and package lifecycle tools. A package can expose its CLI through the cli command or run as a service available to workspace applications. Its manifest and interfaces determine how it receives inputs.

Keeping the environment declared helps teams repeat installation and test an update before using it on important work. Production deployment still needs suitable permissions, monitoring and maintenance.

Shell mode

Shell mode provides LLM command suggestions without initializing a full workspace:

ploinky -shell        # interactive shell
ploinky sh            # alias
psh                   # alias
ploinky -shell <text> # one suggestion

This mode reads API keys from .env files and environment variables. Use /settings for interactive model and provider configuration.

The role in AssistOS

Ploinky handles how capabilities are installed and run. Explorer presents their tasks and outputs in the user's project. Keeping these roles separate lets a team change an agent or runtime without discarding its work.
