Chapter 10: Security Guardian Agent

Security Guardian is a proposed workspace security agent. It would combine conventional scanners and policy checks with AI-assisted triage, then connect findings to the code, packages, identities and tasks involved.

Rules and AI have different jobs

Signatures, declared policies, known vulnerability checks and baselines should use deterministic tools. A language model can help explain an alert or identify relevant context. Its interpretation should remain separate from the evidence and the enforcement decision.

Development and supply chains

The planned checks cover vulnerable code patterns, exposed secrets, dependencies, container images and deployment settings. Software bills of materials, or SBOMs, record the components in a package.

Each finding should point to an affected repository, image, package, model or dataset. License checks and vulnerability findings need their source and version recorded so the team can review them.

Runtime monitoring

Process activity, system calls, logs, network connections and agent tool use can be compared with approved behavior. Unusual access volumes, authentication attempts or configuration changes may warrant review.

For an incident, the agent should assemble a timeline of observed events, tool calls, users and external connections. An anomaly is a reason to investigate, not proof of an attack.

Policy and authorized testing

Administrator policy defines which folders, tools, models and network destinations a capability may use. The runtime should enforce those boundaries. Security Guardian can check observed activity and report violations.

Penetration testing must have an authorized target, scope, time window and intensity. The intended testing workflow covers workspace endpoints, APIs and plugins, with a report of what was exposed and how it was tested.

Evidence in regulated work

Qualification, change control and audit work need records that connect controls to tests and results. Reports may organize evidence against requirements such as 21 CFR Part 11 or EU GMP Annex 11. The organization must validate that mapping for its deployment.

Retain useful findings

Detection rules, false positives, confirmed remedies and incident patterns can be saved as Knowledge Units. These records should state where a rule works and what it misses.

The goal is a report a team can act on, with evidence and a retest path. Security Guardian remains a development direction, not a guarantee that a workspace is protected against every threat.
